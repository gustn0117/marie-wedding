# 팩스 발송 시스템 설계

작성일: 2026-07-26

## 목적

웨딩홀 대상 영업·제휴 문서를 팩스로 보낸다. 이메일을 공개하지 않고 전화·팩스만 두는
웨딩홀이 많아(조사 시 3곳 중 2곳) 이메일 아웃리치만으로는 닿는 범위에 한계가 있다.

## 범위

발송 전용(outbound). 수신 팩스는 이번 범위에서 제외한다 — 수신번호 발급이 필요해
비용·설정이 늘고, 지금 필요한 건 보내는 쪽이다.

## 공급자

계약 전이므로 **공급자 미정 상태로 골격을 완성**한다. 발송만 콘솔 어댑터로 두고
나머지(화면·DB·검증·수신거부)를 전부 만들어, 키를 넣는 순간 켜지게 한다.
SMS 가 이미 같은 상태(코드 완성, NHN 키 없어 off)라 검증된 패턴이다.

조사한 후보:

| 공급자 | 단가 | 비고 |
|---|---|---|
| 솔라피 | 1장당 100원 (공개) | 연동 무료 |
| 팝빌 | 미공개(견적 필요) | 팩스 전문. 발신번호 미등록 시 공용번호 → 수신율 하락 |

어느 쪽이든 **발신번호 사전등록**은 하는 것이 좋다.

## 구조

기존 SMS 어댑터(`src/lib/sms/adapter.ts`)와 동일한 패턴.

```
src/lib/fax/adapter.ts     FaxAdapter 인터페이스 + Console/Solapi/Popbill 구현
src/app/api/admin/fax/     목록·검색·발송·삭제·수신거부 API
src/app/admin/fax/         관리자 화면(메일함과 같은 구조)
```

`FAX_PROVIDER=console|solapi|popbill` 로 교체. 운영에서 console 은 거부한다.

## 데이터

`admin_fax` — 발송 이력. 관리자 메일함(`admin_mail`)과 대칭.

| 컬럼 | 용도 |
|---|---|
| id | PK |
| to_number | 수신 팩스번호(숫자만 정규화) |
| subject | 제목(문서 식별용, 팩스 자체에는 표지로 들어감) |
| file_path | Storage 문서 경로(PDF/이미지) |
| page_count | 장수(요금 산정·표시) |
| status | queued / sent / failed |
| provider | 사용한 공급자 |
| provider_id | 공급자 응답 ID(상태 조회용) |
| error | 실패 사유 |
| created_at / sent_at | 시각 |

`fax_optout` — 수신거부 번호. 발송 시 자동 차단.

| 컬럼 | 용도 |
|---|---|
| number | 수신거부 팩스번호(PK) |
| reason | 접수 경로/사유 |
| created_at | 접수 시각 |

## 컴플라이언스 (기능으로 강제)

광고 팩스는 정보통신망법상 광고성 정보에 해당하고, 상대방 용지·토너를 소모시켜
분쟁 소지가 크다. 나중에 붙이면 이미 보낸 건 되돌릴 수 없으므로 처음부터 넣는다.

1. **(광고) 표기** — 표지 상단에 자동 삽입
2. **수신거부 안내** — 표지에 수신거부 연락처 자동 삽입
3. **수신거부 목록 자동 차단** — `fax_optout` 에 있으면 발송 자체를 거부
4. **야간 차단** — 21:00–08:00(KST) 발송 차단. 별도 동의 없이는 보낼 수 없다

## 재사용

관리자 메일함에서 검증된 것을 그대로 가져온다.

- 여러 수신처 개별 발송(순차) + 진행 표시
- **이미 보낸 곳 중복 경고** — 같은 번호에 보낸 이력을 작성 시 경고
- 목록 검색 + 더 보기 페이지네이션
- 재발송(원클릭)

## 이번 범위에서 제외

- 수신 팩스
- 예약 발송
- 공급자 웹훅 기반 실시간 상태 갱신(1단계는 발송 시점 상태만 기록)
